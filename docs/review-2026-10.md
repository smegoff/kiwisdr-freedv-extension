# October 2026 code review and update

This review targets the external Debian decoder and the standard AM335x Kiwi
extension. It does not move modem processing onto the Kiwi or the AI-64.

## Changes

- Pin the official FreeDV `rade_c` library and adapt its versioned V1/V2 API.
  RADEV2 has independent disabled-by-default gates and a distinct reference
  waveform. Zero EOO bits are valid for V2; no V1 callsign metadata is invented.
- Preserve transient V1 End-of-Over callsigns before sync loss clears modem
  state, and publish new callsign status immediately rather than waiting for
  the periodic status tick.
- Reuse a non-blocking loopback Reporter socket. Reporter pressure must not
  stall the audio/decode path. Refresh the idle station-cache file every 30
  seconds instead of every second; station changes still publish immediately.
- Bound and validate the public station cache, relay only public callsign,
  codec and frequency, and authenticate the entire feed. Capability negotiation
  keeps new decoders compatible with older frequency-only Kiwi extensions.
- Test the exact shared Kiwi poll scanner, including malformed suffixes,
  portable callsigns and legacy requests. Reject unexpected trailing data.
- Keep transmitting stations first in the selector. Selecting one tunes and
  chooses its available codec without starting a stopped session. Preserve
  selection across updates and clear disappeared transmitter selections.
- Collapse optional receive and Reporter controls. Keep Help/Close outside
  the scrollable body, with the status and diagnostics footer reachable when
  both sections are expanded. Retain native Kiwi styling.
- Derive decoder/dashboard asset versions from the package version and prevent
  concurrent Kiwi asset/embed builds with a process-inherited file lock.

## Validation and limitations

The Python, JavaScript behavior and C++ suites cover framing, compatibility,
backend resets, mode selection, malformed station metadata and packaged assets.
Both RADE adapter reference outputs are byte-identical to the pinned official
decoder tools. Measured reference real-time factors were approximately 0.020
for V1 and 0.016 for V2 on the reference decoder guest; these are recorded-sample
measurements, not minimum hardware requirements or impaired-channel scores.

Browser acceptance covers 700D, RADEV1 and RADEV2 reference playback, selection,
Start/Stop and scroll-safe layout. The deployment record carries the exact
release checksums and stability evidence. No live-RF V2 interoperability or
cross-browser acceptance is claimed.

Upstream explicitly advises against on-air V2 use while its waveform, weights
and API are developing. RADEV1 remains the default. Existing 2400A/2400B
receive-chain limitations remain documented in [Mode support](modes.md).
This is an integration/correctness review, not an exhaustive security audit.

See [RADEv2](radev2.md), [Deployment status](deployment-status.md) and the
[official RADE C source](https://github.com/freedv/rade_c).
